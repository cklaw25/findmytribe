SECTION 2 — THE IDEA
================================================================================

PRODUCT NAME: FindMyTribe

ONE-LINE PITCH:
  "Find your people. Right now. In this room."

ELEVATOR PITCH (30 seconds):
  Networking events are broken. Most people arrive, feel lost, and leave
  without a single meaningful connection. FindMyTribe is an AI-powered event
  OS — the organiser gets a live dashboard of the whole room, and each
  attendee gets an AI agent on their phone that finds their most compatible
  people, shows where they are in real-time, and gives them conversation
  starters so they can walk up with confidence.

THE PROBLEM:
  - Social anxiety at events — walking into a room of strangers is terrifying
  - Missed connections — your dream co-founder was 10 feet away. You never met.
  - Inefficient networking — 20 minutes talking to someone with zero overlap
  - No context — everyone has a digital footprint but nobody uses it in realtime

WHO FEELS THIS:
  - Developers at hackathons (meta: that's us right now)
  - Founders at startup events
  - Students at career fairs
  - Anyone at Luma-based social events

THE SOLUTION — HOW IT WORKS:

  TWO VIEWS:

  [HOST / ORGANISER VIEW — like a Luma OS]
  - Full dashboard of all attendees + their current zones
  - Live heatmap: which area of the venue has most people
  - Social graph visualiser
  - Identify isolated attendees to go introduce
  Route: /host

  [ATTENDEE MOBILE VIEW — PWA on their phone]
  - AI generates a "Tribe List" — top 8 people to meet today
    * Category 1: Interest Matches (AI semantic similarity)
    * Category 2: Mutual Friends (shared connections)
  - Each match shows: name, role, match %, reason why, talking points
  - Live event map showing only Tribe List members' current zones
  - Zone check-in: tap which area you're in → your dot moves on the map
  Route: /tribe/[userId]

  FULL FLOW:
    User arrives → opens FindMyTribe → AI agent analyses all attendees
    → generates Tribe List with talking points
    → sees live map of where those people are
    → walks up and starts conversation with context and confidence

LOCATION TRACKING — TWO OPTIONS:

  OPTION A (Primary — build this first):
    Attendee taps which zone they're in (entrance / main hall / workshop /
    chill zone / outside). Simple, works immediately, no hardware needed.

  OPTION B (Stretch — massive differentiator):
    ESP32 BLE beacon on lanyard. Passive tracking — no user action needed.
    Fixed ESP32 anchor nodes around venue detect nearby lanyards via
    Bluetooth signal strength (RSSI) and auto-update their zone.
    Works without WiFi. Impressive hardware demo for judges.

WHY THIS WINS THE AI AGENTS TRACK:
  The matchmaking engine IS an autonomous AI agent:
    PERCEIVE → reads all attendee profile data
    REASON   → multi-step compatibility scoring (interests + social graph + goals)
    ACT      → populates tribe list + generates personalised talking points
    ADAPT    → re-ranks as new people check in
  This is not AI as a chatbot wrapper. AI IS the product.

THE META-DEMO (killer judge moment):
  "We used FindMyTribe at this hackathon to find each other.
   Here's the app. Here are the matches it generated for us this morning."
  Judges are AT the event. They ARE the use case.

SECTION 3 — TECH STACK
================================================================================

BACKEND:   Python 3.11 + FastAPI
AI ENGINE: Anthropic Claude API (model: claude-sonnet-4-6)
DATABASE:  Supabase (Postgres + Realtime subscriptions)
FRONTEND:  TypeScript + Next.js 15 (PWA — works on mobile browser)
HARDWARE:  ESP32 (stretch — BLE beacon tracking)
DEPLOY:    Railway (backend) + Vercel (frontend)

ARCHITECTURE:

  [Attendee Phone PWA]──────┐
  [Host Dashboard Browser]──┤
                            ↓
                   [FastAPI Backend]
                    /      |      \
           [Claude API] [Supabase] [Mock Data]
           (matching)  (realtime)  (15 profiles)

KEY API ENDPOINTS:
  GET  /attendees              → list all attendees
  POST /match/{user_id}        → run AI matchmaking → returns top 8 tribe matches
  POST /location/{user_id}     → update user's current zone
  GET  /locations              → all current zone data
  GET  /event/overview         → host dashboard data

SECTION 6 — HOW TO RUN
================================================================================

STEP 1: Clone the repo
  git clone https://github.com/cklaw25/findmytribe.git
  cd findmytribe

STEP 2: Backend setup
  cd backend
  python -m venv venv
  venv\Scripts\activate           (Windows)
  source venv/bin/activate        (Mac/Linux)
  pip install -r requirements.txt
  copy .env.example .env          → then open .env and paste the API keys

STEP 3: Frontend setup
  cd frontend
  npm install
  copy .env.local.example .env.local → then open .env.local and paste keys

STEP 4: Run everything
  Terminal 1 (backend):
    cd backend && venv\Scripts\activate && uvicorn main:app --reload
    → API running at http://localhost:8000
    → API docs/tester at http://localhost:8000/docs

  Terminal 2 (frontend):
    cd frontend && npm run dev
    → App at http://localhost:3000

  Terminal 3 (demo simulation — run during pitch):
    cd backend && venv\Scripts\activate && python simulate_locations.py
    → Animates attendees moving between zones every 8 seconds

STEP 5: Test a match (once API key is set)
  Visit: http://localhost:8000/docs
  POST /match/usr_001 → should return 8 AI-matched profiles with talking points

SECTION 7 — SUPABASE SETUP (Dev 2 does this once for the whole team)
================================================================================

1. Go to https://supabase.com → New project → name: findmytribe
2. Go to SQL Editor → paste and run this:

-------- COPY FROM HERE --------
create table profiles (
  id text primary key,
  name text, role text, company text, bio text,
  interests text[], goals text, twitter text, github text,
  past_events text[], mutual_friend_ids text[],
  created_at timestamptz default now()
);

create table locations (
  user_id text primary key,
  zone text default 'entrance',
  updated_at timestamptz default now()
);

create table tribe_list (
  id uuid primary key default gen_random_uuid(),
  user_id text, match_id text,
  score float, reason text, talking_points text[],
  match_type text, source text,
  generated_at timestamptz default now()
);

alter publication supabase_realtime add table locations;

JUDGE Q&A — LIKELY QUESTIONS:
  "Privacy issue?"
    → Fully opt-in. Location only visible to your tribe list, not 500 strangers.
      Auto-deleted after event ends.
  "Why not LinkedIn?"
    → LinkedIn is passive and async. This is real-time and event-aware.
      You know who's in the room right now and where.
  "Why AI and not just tag filtering?"
    → Tags give you 50 results. Claude understands nuance — two people both
      building "autonomous systems" even if one calls it robotics and the
      other calls it AI agents.
  "Business model?"
    → B2B SaaS: organisers pay per event. Freemium for attendees.
      Sponsorship: "Top match sponsored by Anthropic."
  "Why not Bumble BFF?"
    → Bumble is async, romantic-leaning, not event-specific. This is
      professional, real-time, and context-aware.
  "Could Luma just build this?"
    → Yes. That's the exit — acquire or deep partnership. Until then,
      we're the intelligence layer on top of their platform.
